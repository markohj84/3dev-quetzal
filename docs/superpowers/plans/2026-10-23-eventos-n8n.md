# Eventos salientes a n8n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cada aviso que hoy sale por correo/WhatsApp sale también como `POST` JSON (opcionalmente firmado) al webhook de n8n del cliente.

**Architecture:** Un tercer canal en `createLeadNotifier` (`core/notify.ts`), en el mismo `Promise.allSettled` que correo y WhatsApp. La URL y el secreto llegan por `NotifySecrets.webhook`, que arma `app/assistant.ts` con `clientEnv`. Rutas y esquema no cambian.

**Tech Stack:** TypeScript corrido directo por Node (type stripping), `node:crypto`, `node:http` (solo en la autoprueba), `fetch` con `AbortSignal.timeout`.

**Spec:** `docs/superpowers/specs/2026-10-23-eventos-n8n-design.md`

## Global Constraints

- Ningún archivo bajo `core/` nombra a un cliente (`npm run check:boundary`): el encabezado de firma es `x-signature-256`, nada con "quetzal".
- `core/` no lee variables de entorno: URL y secreto llegan por `secrets`.
- Variables: `<PREFIJO>__NOTIFY_WEBHOOK_URL`, `<PREFIJO>__NOTIFY_WEBHOOK_SECRET` (vía `clientEnv`).
- Firma: `x-signature-256: sha256=<HMAC-SHA256 hex del cuerpo exacto enviado>`.
- Timeout 5 s, sin reintentos; una falla es una línea de log y nunca cuesta correo ni WhatsApp.
- Precedencia de `event`: `inbound` > `booking` > `lead` > `interest`.
- Campos ausentes (`lead`, `booking`, `inbound`, `reachAt`, `panelUrl`) van como `null`.
- Comentarios solo para el *por qué*; código en inglés, texto de cara al usuario en español.

## Review Focus

1. Webhook que acepta la conexión pero nunca contesta → `notify()` termina en ~5 s y el correo sale igual (pin: Task 1, caso "colgado").
2. Webhook que responde 500 → una línea de log, `notify()` no lanza (pin: Task 1, caso 500).
3. Firma calculada sobre un cuerpo distinto al enviado (p. ej. re-serializado) → n8n la rechazaría; la prueba verifica contra el cuerpo crudo recibido (pin: Task 1).
4. Cliente sin URL configurada en modo compartido → ninguna petición, nunca la URL de otro cliente (pin: Task 1 "sin URL"; `clientEnv` ya no tiene respaldo en multi-tenant).
5. Evento de Calendly (sin transcripción, `channel: 'calendly'`) → `event: 'booking'`, `transcript: []` (pin: Task 1, precedencia).

```ts
/** The same order the email subject uses: the most specific thing that happened wins. */
export function alertEvent(alert: LeadAlert): 'inbound' | 'booking' | 'lead' | 'interest' {
  if (alert.inbound) return 'inbound';
  if (alert.booking) return 'booking';
  if (alert.captured) return 'lead';
  return 'interest';
}

// ponytail: no retries — with the flow down the event is lost; add a queue when a client needs one.
async function sendWebhook(alert: LeadAlert, webhook: NotifySecrets['webhook']): Promise<void> {
  if (!webhook?.url) return;
  const body = JSON.stringify({
    event: alertEvent(alert),
    clientId: webhook.clientId,
    channel: alert.channel,
    contactId: alert.contactId,
    at: new Date().toISOString(),
    lead: alert.captured ?? null,
    booking: alert.booking ?? null,
    inbound: alert.inbound ?? null,
    reachAt: alert.reachAt ?? null,
    panelUrl: alert.panelUrl ?? null,
    transcript: alert.transcript,
  });
  const headers: Record<string, string> = { 'Content-Type': 'application/json' };
  if (webhook.secret) {
    headers['x-signature-256'] = `sha256=${createHmac('sha256', webhook.secret).update(body).digest('hex')}`;
  }
  // A slow flow must not hold the reply: five seconds, then a log line.
  const res = await fetch(webhook.url, { method: 'POST', headers, body, signal: AbortSignal.timeout(5000) });
  if (!res.ok) console.error('webhook error', res.status);
}
```
